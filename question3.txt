Solution:

cd breach_response
cp evidence/log_dump.txt log_dump.txt
chmod 755 evidence
mv evidence secure/
chmod 555 secure/evidence
chmod 644 reports/incident_summary.txt
echo "Breach confirmed" >> reports/incident_summary.txt
chmod 444 reports/incident_summary.txt
echo "Forensics Complete" > secure/forensics_report.txt
chmod 600 secure/forensics_report.txt
chmod 644 reports/incident_summary.txt
echo "Escalated to security team" >> reports/incident_summary.txt
chmod 444 reports/incident_summary.txt


Approach:

First, I changed my current working directory using the cd breach_response command to navigate into the workspace.Next, I needed to copy the raw log dump file from evidence/log_dump.txt to the root workspace directory. I used cp evidence/log_dump.txt log_dump.txt to make that copy.
then, I needed to move the entire evidence directory into the secure folder. Since the original directory required permission changes to move and secure, I used chmod 755 evidence to grant access, mv evidence secure/ to move it, and chmod 555 secure/evidence to lock down its permissions.
After that, I needed to log the incident status. I updated reports/incident_summary.txt by temporarily granting write permissions with chmod 644, appending "Breach confirmed" using echo "Breach confirmed" >> reports/incident_summary.txt, and locking it back with chmod 444.
Following that, I needed to create the forensics report. I used echo "Forensics Complete" > secure/forensics_report.txt to create the file with the exact required text, and set its file permissions to owner-only using chmod 600 secure/forensics_report.txt.
Finally, I needed to append the escalation note to the incident summary. I unlocked reports/incident_summary.txt with chmod 644, appended "Escalated to security team" using echo "Escalated to security team" >> reports/incident_summary.txt, and secured the file back to read-only mode with chmod 444.
